# Changelog

## 1.0.0 — fascon-gc roots behind local own, the F3902 call-graph case, masked column RMW checks (Fascon 1.0) / ローカルの own の中の fascon-gc の根・F3902 の呼び出し先・条件付き一括更新の検査（Fascon 1.0）

The version name stays Fascon 1.0 (1.0.0). / 版の名前は Fascon 1.0（1.0.0）のまま。

- **fascon-gc**: gc_arena Ids inside local `own T`, `Option<own T>`, structs with own fields and arrays of them are roots (locals, by-value parameters, temporaries, return slots). Moves, drops, overwrites and `.take()` clear the C variable before the storage goes away (`fsc_own_drop_at_*`), temporaries leave the roots right before a call or literal takes them, and `#[on_drop]` runs while the value is still a root. The runtime ignores nested collections, masks interrupts while marking (`FASCON2_PREEMPT`), walks each chain once, parks a task switch during a shared collection (QEMU BSPs) and has a test-only alias check (`-DFASCON2_GC_ALIAS_CHECK`). See section 5.3.1 of `docs/SPEC-1.0-UNIVERSAL.ja.md`. / **fascon-gc**: ローカル・仮引数・一時値・戻り値の入れ物の own T・Option<own T>・own フィールドを持つ構造体・その配列の中の Id も根になります。移動・解放・上書き・take は記憶域が消える前に C の変数を NULL / 0 にし、一時値は呼び出し・リテラルへ渡す直前に根から外れ、#[on_drop] は値が根のまま走ります。
- **F3902** (`--target hpc`): a `for id in @a` loop whose body calls a function that rebuilds mirror columns of `a` is reported too (the write set of the body includes its callees). New test `tests/err/f3902_hpc_mirror_callee.fsc`; the quick fix still runs the work on core 0. / **F3902**: 本体から呼ぶ関数が写しを作り直すループも報告します。
- **Masked column RMW**: new kernel test `tests/cols/rmw_untouched.c` (all 12 kernels; zero words never load or store the column, checked with PROT_NONE pages). / 条件付き一括更新の走査関数の検査を追加（0 の語は列に触れない）。
- Programs without gc_arena generate the same C, byte for byte (183 programs × 3 modes, `tools/compare_c.py`); the test suite passes 402 of 402 with `--qemu`. / gc_arena を使わないプログラムの C は 1 バイトも変わりません。テストは `--qemu` で 402 件すべて PASS。
- **Module cache**: importing a standard library module that imports another one (`import net::tcp;`) no longer creates a stray `<std>/` folder in the current folder (Linux and macOS). The generated C is unchanged. / **モジュールのキャッシュ**: 別のモジュールを取り込む標準ライブラリのモジュール（`import net::tcp;`）を使うと、今いるフォルダに `<std>/` ができていた不具合を直しました（Linux・macOS）。生成 C は変わりません。
- **Release files**: one VSIX for Windows x64, Linux x64 / arm64 and macOS (universal binary), each with the 0.1.0 engine. The Windows build was run under Wine and the Linux arm64 build under qemu-user (byte-identical C, or the same failure, for 247 programs in five modes against the Linux x64 build); the macOS build was not run. When `fascon-core` is missing, `fascon` now says so for files with 0.1-only syntax (F2900). / **配布物**: VSIX 1 つで Windows x64・Linux x64 / arm64・macOS（ユニバーサルバイナリ）、どれも 0.1.0 エンジン入り。Windows 版は Wine、Linux arm64 版は qemu-user で動かし、247 本 × 5 モードで Linux x64 版と同じ C（または同じ失敗）になることを確かめました。macOS 版は動かしていません。`fascon-core` が無いとき、0.1 だけの構文のファイル（F2900）にはその旨を出すようにしました。
- **License**: MIT OR Apache-2.0, at your option (`LICENSE-MIT`, `LICENSE-APACHE`). Pull requests are not accepted; forks and extensions are welcome (`CONTRIBUTING.md`). / **ライセンス**: MIT OR Apache-2.0（どちらか好きな方）。プルリクエストは受け付けず、フォークと拡張は歓迎します。
- Known issue found while testing, left as it is because fixing it would change the C of programs without gc_arena: reading a field straight from an own returned by a call (`make().field`) never frees that own (LeakSanitizer reports it with `-DFASCON2_HEAP_MALLOC`). Bind the result first (`let m = make(); m.field`). / テスト中に見つけた既存の問題（直すと gc_arena の無いプログラムの C が変わるので、そのまま）: 呼び出しが返した own から直接フィールドを読む（`make().field`）と、その own が解放されません。先に `let m = make();` で受けてください。

## 1.0.0 — integration of multi-core, interrupts, user space and fascon-gc (Fascon 1.0) / マルチコア・割り込み・ユーザー空間・fascon-gc の統合（Fascon 1.0）

The version name stays Fascon 1.0 (1.0.0). Specification: `docs/SPEC-1.0-INTEGRATION.md`. / 版の名前は Fascon 1.0（1.0.0）のまま。仕様は `docs/SPEC-1.0-INTEGRATION.ja.md`。

- **SMP kernels**: `spawn_on` together with `irq`, `task_arena`, `dma_arena`, `syscall` and `trap` (F2614 retired); task tables, run queues and timers are per core. New error F2616 (a shared-interrupt handler touching a per-core arena); F2601, F2603 and F2622 now also cover the multi-core cases. / **マルチコアのカーネル**: `spawn_on` と irq・task_arena・dma_arena・syscall・trap の併用（F2614 は廃止）。新しいエラー F2616、F2601・F2603・F2622 はマルチコアの場合も扱います。
- **User space**: `user_mem` in multiples of 4 KiB with demand paging (F2803 relaxed), one address space per task (ASID / CR3, no TLB flush on switches), EL0 and ring 3 processes preempted on every core, system-call windows copied once into shadow buffers (no double reads). / **ユーザー空間**: 4 KiB 単位の `user_mem` と要求時ページング、タスクごとのアドレス空間、全コアのプロセス、影バッファへの 1 回だけの写し。
- **Panic** stops every core (SGI 2 on AArch64, NMI on x86_64), even cores in the middle of printing. / **パニック**で全コアが止まります（出力の最中のコアも）。
- **fascon-gc**: Ids in expression temporaries and inside channels stay roots during `gc_collect`. / **fascon-gc**: 式の一時値とチャネルの中の Id が根になります。
- **x86_64 virtual BIOS** (`fascon.target` = x86_64): 4 cores, LAPIC timer (irq 27), HPET clock, ring 3, IPI shootdown, NMI; the same kernel sources run on AArch64 and x86_64. / **x86_64 の仮想 BIOS**: 4 コア・LAPIC タイマー・HPET・Ring 3・IPI・NMI。同じカーネルのソースが両方で動きます。
- **Porting**: the reference platform layer `bsp/portable-stub/` and `tools/cross_check.py` (generated C compiled with `-Werror` and linked for ARMv7, MIPS64, RISC-V64, AArch64, x86_64). / **移植**: 参照プラットフォーム層と、5 アーキテクチャの翻訳・リンクの検査。
- **Dictionary**: every error code the 1.0 compiler can emit now has an entry in both languages (42 codes added to the 1.0 dictionary, 29 of which had no entry anywhere, such as F0004, F0061 and F2804; F0001, F0308 and F0599 rewritten for 1.0), the empty explanations and remedies are filled in, F2614 is marked retired, F2616 is added, and new entries describe `chan`, `fascon_plat_*`, per-task address spaces, shadow buffers and the panic stop. `fascon dict` shows exact name / alias matches of either dictionary first (`fascon dict match` shows `match`), `fascon dict TERM --json` no longer returns the whole 0.1.0 dictionary, and `fascon dict -- --target` looks up terms that start with `--`. `tools/check_dictionary.py` (audit) and `tools/sync_dictionary.py` (copies `data/dictionary.json` into the extension dictionaries) run in the test suite. / **辞書**: 1.0 のコンパイラが出しうるエラー番号すべてに日英の項目（1.0 の辞書に 42 件追加。うち F0004・F0061・F2804 など 29 件はどの辞書にも無かったもの。F0001・F0308・F0599 は 1.0 向けに書き直し）。空だった説明と対処を補い、F2614 を廃止と明記、F2616 を追加し、`chan`・`fascon_plat_*`・タスクごとのアドレス空間・シャドウバッファ・パニック時の全コア停止の項目を足しました。`fascon dict` はどちらの辞書でも名前・別名の完全一致を先に出し（`fascon dict match` で match の項目）、`--json` に 0.1.0 の全項目が混ざる不具合を直し、`fascon dict -- --target` で `--` で始まる語も引けます。監査 `tools/check_dictionary.py` と同期 `tools/sync_dictionary.py` をテストに入れました。
- Programs that do not use the new features generate the same C (234 of 240 compared; the 6 others use `spawn_on` with `--target x86_64`, which is multi-core now). The test suite passes 317 of 317 with `--qemu`. / 新機能を使わないプログラムの C は不変（比較 240 件中 234 件が一致。残る 6 件は `--target x86_64` で `spawn_on` を使うもの）。テストは `--qemu` で 317 件すべて PASS。
- Not verified: the PCID path on x86_64 (QEMU TCG has no PCID), ARMv7 / MIPS64 execution (compiled and linked only), real hardware, and the cross-built macOS executable (the Windows one ran only under Wine). / 未確認: x86_64 の PCID の道（TCG に PCID なし）、ARMv7・MIPS64 の実行、実機、クロスビルドした macOS / Windows の実行ファイル。

## 1.0.0 — own fields of any type and callbacks / どんな型でも持てる own フィールドとコールバック

The version name stays 1.0 (1.0.0). Existing programs compile to the same C as before, comments aside (`tools/compare_c.py` on every example, test and the benchmark). Details: section 10 of `docs/SPEC-1.0-EXT.md`. / 版の名前は 1.0（1.0.0）のままです。既存のプログラムの C は注釈を除いて以前と同じです（`tools/compare_c.py` ですべての例・テスト・ベンチマークを比較）。詳しくは `docs/SPEC-1.0-EXT.ja.md` の 10 章にあります。

- own fields of any value type: `struct MyContext { buffer: own i32, size: i32 }`, `own [u8; 4096]`, `own Str`, `Option<own i32>`, `own_alloc(i32)` / `own_alloc([u8; N])`. `*` reaches the contents of an own (`*ctx.buffer += 1;`); `ctx.buffer = own 7;` replaces the own and frees the old one. In C an `own i32` is an `int32_t *` in an own region; drop / clone glue `fsc_own_drop_T_<type>` / `fsc_own_clone_T_<type>`; own_alloc creates every own child (also `own i32`) zero-filled. / どんな値の型でも持てる own フィールド。`*` で own の中身を読み書きし、`ctx.buffer = own 7;` で own ごと差し替え（古い own は解放）。C では所有リージョンの `int32_t *`。own_alloc は own の子（`own i32` も）をすべて 0 で作ります。
- A struct with own fields is move-only: moves clear the source, and scope ends, overwrites, `drop` and arena frees free every own inside. F0382 (use after a whole-struct move, including field reads and writes through `*`) and F0507 (moving an own field or a non-copyable `*b` out) make double frees unwritable; a write to a field of a moved value is now reported once (it was reported twice, for the variable and for the field). / own フィールドを持つ構造体は移動専用。移動元は空になり、スコープの終わり・上書き・`drop`・アリーナの free で中の own をすべて解放。F0382（構造体まるごとの移動の後の使用。フィールドの読み書きと `*` を通した書き込みを含む）と F0507（own のフィールドやコピーできない `*b` の取り出し）で二重解放は書けません。移動済みの値のフィールドへの書き込みは 1 回だけ報告します（以前は変数とフィールドで 2 回）。
- Function pointers `fn(&mut i32) -> R`: function names as values, parameters, locals, struct fields (`(h.on_click)(&mut b)`), static tables (`static OPS: [fn(&mut i32); 2] = [inc, dbl];`), `Option<fn(..)>`; typedef'd C function pointers. / 関数ポインタ `fn(&mut i32) -> R`: 関数の名前を値として、引数・ローカル・構造体のフィールド・static の表・`Option<fn(..)>` に。C では typedef した関数ポインタ。
- **F0520 — reference escape constraint violated**: callbacks (functions with reference parameters used as values) must be stack_only. An escape analysis (summaries per function and reference parameter, a least fixpoint over the call graph; references made from references, wrapping values, locals and callees are followed) reports a reference stored into an arena / static / MMIO / the caller's place / an own, moved into a by-value parameter or returned, with a root-cause timeline from the higher-order call to the escape; F0515 / F0308 at the same places are folded into it. / **F0520 — 参照のエスケープ制約違反**: コールバック（参照の引数を持ち、値として使われた関数）は stack_only でなければなりません。エスケープ解析（関数と参照引数ごとの要約、呼び出しグラフ上の最小不動点）が、アリーナ・static・MMIO・呼び出し元の場所・own への保存、値渡しの引数への移動、返却を、高階関数の呼び出しから逃げ先までのタイムライン付きで報告します。同じ場所の F0515 / F0308 は F0520 にまとめます。
- Calls through function pointers carry the union of the effects of the functions that can be passed there (candidates narrowed per parameter), so F2502 names a callback that may touch an arena the caller has lent a reference into; bump-arena call regions and column mirrors follow indirect calls too. / 関数ポインタを通した呼び出しは渡されうる関数の効果の和を持ち（引数ごとに候補を絞る）、呼び出し元が参照を貸しているアリーナを触りうるコールバックを F2502 で名指しします。バンプアリーナの呼び出しリージョンと列の写しも間接呼び出しを追います。
- New errors F0520 and F0618 (calling a non-function); F2301 now means an own of something an own cannot hold (`()`, `own own T`, a function pointer); F0515 also covers `own x` of a reference and references in function pointer results. / 新しいエラー F0520・F0618。F2301 は own が所有できないものへの own、F0515 は参照の `own x` と関数ポインタ型の戻り値の参照も扱います。
- Files with `own i32` or `fn(..)` types alone now open in the 1.0 engine. / `own i32` や `fn(..)` の型だけを使うファイルも 1.0 エンジンで開きます。
- VS Code: example `own_callbacks.fsc` ("Open a 1.0 Example"), dictionary entries `fn(T) -> R`, `stack_only`, `own_alloc(T)`, F0520, F0618 (and updated `own T`, F0507, F2301, F2502), snippets `ownfield`, `foreachfn`, `handlerfn`, the explanation of F0520 in "Explain Error". / VS Code: 例 `own_callbacks.fsc`、辞書の項目、スニペット、「エラーを解説」の F0520 の解説。
- Tests 113 → 136 (with `--qemu`; 85 → 107 without): `tests/ok/own_fields.fsc`, `tests/ok/callbacks.fsc`, `examples/own_callbacks.fsc` (PC, BIOS-less AArch64, x86_64 virtual BIOS) and 16 error cases; the new programs also pass AddressSanitizer / UBSan / LeakSanitizer with `-DFASCON2_HEAP_MALLOC`. / テストは 113 → 136 件（`--qemu` 付き。なしでは 85 → 107 件）。新しいプログラムは `-DFASCON2_HEAP_MALLOC` で AddressSanitizer / UBSan / LeakSanitizer も通ります。

## 1.0.0 — extensions: one language for BIOS, OS, GUI and applications on x86_64 and AArch64 / 拡張: x86_64 と AArch64 の BIOS・OS・GUI・一般アプリを 1 つの言語で

The version name stays 1.0 (1.0.0). Existing programs compile to the same C as before, comments aside (`tools/compare_c.py` compares every example and test against the previous build), so scan speed is unchanged. Details: `docs/SPEC-1.0-EXT.md`. / 版の名前は 1.0（1.0.0）のままです。既存のプログラムの C は注釈を除いて以前と同じなので（`tools/compare_c.py` ですべての例とテストを比較）、走査の速さは変わりません。詳しくは `docs/SPEC-1.0-EXT.ja.md` にあります。

- Type inference: `let` needs no annotation (`let task = create_process(100);`); variables whose type is settled later are handled by two type-checking passes per function; F0282 remains only for a type still unknown at the base of a field, method or index. / 型推論: `let` に注釈は要りません。型が後で決まる変数は関数ごとの 2 周の型検査で扱います。F0282 は、型が決まらないままフィールド・メソッド・添字の土台に使われたときだけです。
- `@` abolished (optional): `pcb_table[id].id = 100;` is the generation-verified `.get_mut(id)`; `@name` still works and always means the region. Declarations may come in any order (two-pass analysis; F2104 only for names declared nowhere). / `@` の廃止（省略可）: `pcb_table[id].id = 100;` は世代タグで検証する `.get_mut(id)` と同じ。`@名前` も使え、いつもリージョンを指します。宣言の順序は自由です（2 パス解析。F2104 はどこにも宣言されていない名前だけ）。

  - A loop that only adds unsigned fields of the slot into an outer unsigned variable becomes one straight, unrolled, branch-free scan (`fsc_reduce_*`, `const f20_arena_t(tag) *__restrict__ arena`). Dead slots are zero-filled on free, so the live marks are not read. Overflow is detected exactly, once, at the end. / スロットの符号なしフィールドを外の符号なしの変数へ足すだけのループは、表を一直線に走査する展開済みで分岐のない関数（`fsc_reduce_*`）になります。解放したスロットは 0 で埋めるので生存印は読みません。あふれは最後に 1 回だけ正確に判定します。
  - Benchmark (60,000 tasks, same session): the scan went from 1.38 / 1.25 to 0.94 / 0.91 ns per task (gcc / clang). / ベンチマーク（6 万タスク・同じ回の比較）: 走査は 1 タスク 1.38 / 1.25 → 0.94 / 0.91 ns（gcc / clang）。
- New example `vruntime_scan.fsc` (a 65,536-slot arena = 16 | 16) and a latch test harness (`tests/latch`, 103 checks). / 新しい例 `vruntime_scan.fsc`（65,536 スロット = 16 | 16）とラッチのテスト（`tests/latch`、103 項目）。
- F2103 now also rejects a bare array as an arena element (it used to produce C that did not compile). / F2103 は配列をそのまま要素にしたアリーナも拒否するようになりました（以前はコンパイルできない C を出していました）。
- `fascon regions` reports generation checks as elided / branch-free / `Option` lookups / stop on the spot, and the K, generation width and lifetime of every arena. / `fascon regions` は世代検査を「証明で省略・分岐なし・Option のルックアップ・その場で停止」に分けて数え、アリーナごとの K・世代の幅・寿命を表示します。
- From the 1.0 preview: arenas with generation-tagged Ids, arena colouring (F2101), kind-bounded Id aliases (F2102), arena effect analysis (F2502), `own T` trees packed into one allocation, fixed-address MMIO regions with compile-time bounds checks (F2201) and overlap checks (F2203), the commands Run on This PC / Boot in QEMU / Save Screenshots / Open a 1.0 Example / Show Version and Tool Check, and a language server that relays 0.1 files to the bundled 0.1.0 engine. / 1.0 のプレビューから（名前の変更のみ）: 世代タグ付き Id のアリーナ・色分け（F2101）・要素型で縛った別名（F2102）・アリーナ効果（F2502）・確保 1 回の `own T` のツリー・コンパイル時に境界（F2201）と重なり（F2203）を検査する固定番地の MMIO リージョン、各コマンド、0.1 のファイルを同梱の 0.1.0 エンジンへ中継する言語サーバー。
